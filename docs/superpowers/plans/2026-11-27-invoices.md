# Invoices Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Admins bill a client's past Agenda occurrences (priced from the property's visit price) into a numbered French PDF invoice, saved as an admins-only Document linked to the client, with unpaid / paid / cancelled status and optional email to the client.

**Architecture:** New backend package `backend/app/invoices/` (pure money + billing helpers, a PDF renderer, a service, routes), migration `0022`, a `visit_price` column on properties, an attachment field on emails. Frontend gets an `invoices/` area (list, invoice page, bill dialog opened from the client page) and a price field on the property dialog.

**Tech Stack:** FastAPI, SQLAlchemy 2, Postgres, Alembic (hand-written SQL), `fpdf2` (new dependency, pulls Pillow) for the PDF, React + TanStack Query + react-i18next, vitest.

**Spec:** `docs/superpowers/specs/2026-11-27-invoices-design.md`

## Global Constraints

- Follow `CLAUDE.md`: every route uses `guard()` (`guard(csrf=False)` for GETs), authority through `app/auth/policy.py`, audit via `audit.log(...)` only, error bodies `{"error": "<code>"}`, test first and watch it fail.
- Admins and super admin only (`policy.PRIVILEGED`). Staff get `403 {"error":"forbidden"}` on every invoice route, never receive `visit_price`, never see invoice documents.
- First invoice number is **7**, shown as `007` (`f"{n:03d}"`); numbers are gap-free, never reused (cancelled invoices keep theirs, invoices are never deleted).
- No tax calculation: `tax` is always `0.00` and the PDF prints "Taux de TVA 0,00 $".
- Money is `numeric(10,2)` in the database, `Decimal` in Python, and a string with two decimals in JSON (`"195.00"`). Amounts: `0 ≤ x ≤ 99999.99`, at most 2 decimal places.
- An occurrence `(event_id, occurrence_date)` — `occurrence_date` is the occurrence's **original** date, as in `event_exceptions` — is on at most one non-cancelled invoice, enforced by a partial unique index.
- "Billable" = the occurrence's actual date is ≤ today in `COMPANY_TZ` (`app/schedule/service.py`), it is not cancelled, and the event's `client_id` is the invoice's client.
- PDF: French only, A4 portrait, layout of `/home/evandro/Downloads/KMK Facture.pdf`. Company block (fixed, in code): `Lévis - QC`, `Tél. : (367) 331-2003`, `info@kmk-entretien.com`, `kmk-entretien.com`, `NEQ : 3382547134`, and the italic line `Nous vous remercions de votre confiance.`
- The PDF is stored once at creation as a `Document`: `visibility="admins"`, `client_id` = the client, title `Facture 007`, file name `Facture-007.pdf`, category "Factures" (created if missing, icon `🧾`). On cancel the title becomes `Facture 007 (annulée)`.
- New UI strings go into all four locale files (`fr-CA`, `en`, `pt-BR`, `es`), keys starting with `inv`.
- Migration `0022` written by hand; `app/models.py` kept in step; `GRANT SELECT, INSERT, UPDATE, DELETE ... TO kmk_app` for new tables.
- Version: `0.4.0` → `0.5.0` in `frontend/package.json` and `backend/pyproject.toml`.
- Commit messages end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. **Names and addresses outside Latin-1** (`Łukasz Nguyễn`, an emoji in a property name): the PDF must render with an embedded TTF font, not fail with a 500. Test in Task 4.
2. **Two admins bill the same occurrence at the same time:** one invoice is created, the other gets `409 {"error":"already_billed"}`, and numbers stay consecutive. Test in Task 5.
3. **A moved occurrence** (exception with a new `start_date`): it is keyed by its original date, shows its new date, is billable only once its new date is past, and a cancelled one is never offered. Test in Task 3.
4. **A long invoice** (40 lines for a fortnight across several properties): the PDF breaks across pages, totals after the last line, footer on every page. Test in Task 4.
5. **Client edited or deleted after billing:** the invoice keeps its billed-to snapshot, still lists, still downloads (re-rendered if its Document was deleted). Test in Task 6.

Migration SQL (the shape the rest of the plan relies on):

```sql
ALTER TABLE properties ADD COLUMN visit_price numeric(10,2) CHECK (visit_price IS NULL OR visit_price BETWEEN 0 AND 99999.99);

CREATE TABLE invoices (
  id bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  number integer NOT NULL UNIQUE CHECK (number > 0),
  client_id bigint REFERENCES clients(id) ON DELETE SET NULL,
  bill_name text NOT NULL, bill_address text, bill_city text, bill_phone text, bill_email text,
  issued_on date NOT NULL,
  status text NOT NULL DEFAULT 'unpaid' CHECK (status IN ('unpaid','paid','cancelled')),
  paid_on date,
  subtotal numeric(10,2) NOT NULL CHECK (subtotal >= 0),
  tax numeric(10,2) NOT NULL DEFAULT 0 CHECK (tax >= 0),
  extra numeric(10,2) NOT NULL DEFAULT 0 CHECK (extra >= 0),
  total numeric(10,2) NOT NULL CHECK (total >= 0),
  sent_at timestamptz, cancelled_at timestamptz,
  document_id bigint REFERENCES documents(id) ON DELETE SET NULL,
  created_by bigint REFERENCES users(id), created_at timestamptz NOT NULL DEFAULT now(),
  updated_by bigint REFERENCES users(id), updated_at timestamptz NOT NULL DEFAULT now(),
  CONSTRAINT invoices_paid_has_date CHECK ((status = 'paid') = (paid_on IS NOT NULL))
);
CREATE INDEX invoices_client_idx ON invoices (client_id);

CREATE TABLE invoice_lines (
  id bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  invoice_id bigint NOT NULL REFERENCES invoices(id) ON DELETE CASCADE,
  position integer NOT NULL,
  description text NOT NULL CHECK (char_length(btrim(description)) BETWEEN 1 AND 200),
  amount numeric(10,2) NOT NULL CHECK (amount BETWEEN 0 AND 99999.99),
  event_id bigint REFERENCES events(id) ON DELETE SET NULL,
  occurrence_date date,
  live boolean NOT NULL DEFAULT true,
  CONSTRAINT invoice_lines_event_has_date CHECK (event_id IS NULL OR occurrence_date IS NOT NULL)
);
CREATE INDEX invoice_lines_invoice_idx ON invoice_lines (invoice_id);
CREATE UNIQUE INDEX invoice_lines_once ON invoice_lines (event_id, occurrence_date) WHERE live AND event_id IS NOT NULL;
GRANT SELECT, INSERT, UPDATE, DELETE ON invoices, invoice_lines TO kmk_app;
```
